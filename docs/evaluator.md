# Оценщик качества LLM-агента

## 1. Роль оценщика

Оценщик получает результаты запуска агента и по ним считает показатели качества ответа, качества поиска по документам и эффективности выполнения запроса. Одинаковые правила оценки применяются к исходной версии агента и ко всем кандидатам, поэтому результаты разных версий можно сравнивать между собой.

Сводные показатели используются системой при сравнении версий и выборе следующего шага оптимизации, а также показываются пользователю. Подробные значения по отдельным тестовым запросам сохраняются внутри системы и нужны для диагностики и дальнейшей оптимизации.

## 2. Что получает оценщик

Для каждого тестового запроса используются две группы данных: эталонная разметка и результат запуска агента.

| **Источник**      | **Что требуется**                                                                                 | **Для чего используется**                                             |
|-------------------|---------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------|
| Разметка          | Идентификатор запроса, вопрос, эталонный ответ, набор эталонных фактов.                           | Эталон для оценки полноты и точности ответа, а также качества поиска. |
| Результат запуска | Финальный ответ агента.                                                                           | Fact Recall и Fact Precision.                                         |
| Результат запуска | Найденный контекст и результаты выполнения инструментов.                                          | Retrieval Fact Recall, Faithfulness и Context Precision.              |
| Результат запуска | Число вызовов инструментов, число успешных вызовов, общее число токенов, время обработки запроса. | Сравнение эффективности разных версий агента.                         |

## 3. Метрики качества ответа и поиска

Основная единица оценки — эталонный факт. Для каждого вопроса заранее размечается набор фактов, которые должны присутствовать в хорошем ответе. Основные метрики считаются с помощью RAGAS; эталонный ответ и размеченные факты используются как эталонная информация для сравнения.

### 3.1. Fact Recall

Главная метрика качества ответа. Она показывает, какая доля обязательных эталонных фактов попала в финальный ответ агента. Пропуск нужного факта считается более существенной проблемой, чем появление дополнительной подробности.

**Данные для расчёта.** Из разметки — эталонный ответ и набор эталонных фактов; из результата запуска — финальный ответ агента.

**Как считается.** Доля эталонных фактов, смысл которых отражён в финальном ответе. Для проекта метрика интерпретируется как полнота ответа по обязательным фактам.

**RAGAS.** Factual Correctness в режиме recall.

### 3.2. Fact Precision

Показывает, какая часть фактических утверждений в ответе соответствует эталонной информации. Метрика помогает заметить ответы, в которых к правильной информации добавлено слишком много лишних или нецелевых фактов. При сравнении версий она имеет меньший приоритет, чем Fact Recall.

**Данные для расчёта.** Из разметки — эталонный ответ и набор эталонных фактов; из результата запуска — финальный ответ агента.

**Как считается.** Доля фактических утверждений ответа, которые соответствуют эталонной информации.

**RAGAS.** Factual Correctness в режиме precision.

### 3.3. Retrieval Fact Recall

Показывает, какую часть необходимой информации агент смог найти до формирования финального ответа. Метрика позволяет отличить проблему поиска от ситуации, когда нужная информация была найдена, но затем потерялась при подготовке ответа.

**Данные для расчёта.** Из разметки — эталонный ответ и набор эталонных фактов; из результата запуска — результаты выполнения всех инструментов и найденный контекст.

**Как считается.** Доля эталонных фактов, которые подтверждаются информацией, полученной агентом через поиск и инструменты.

**RAGAS.** Context Recall.

### 3.4. Faithfulness

Показывает, насколько фактические утверждения финального ответа опираются на информацию, которую агент действительно получил во время выполнения запроса.

**Данные для расчёта.** Из разметки — вопрос; из результата запуска — финальный ответ и найденный контекст, включая результаты инструментов, использованные агентом.

**Как считается.** Доля утверждений финального ответа, которые подтверждаются найденным контекстом.

**RAGAS.** Faithfulness.

### 3.5. Context Precision

Показывает качество найденного контекста: насколько высоко в выдаче расположены полезные фрагменты и насколько поиск не перегружен нерелевантными результатами.

**Данные для расчёта.** Из разметки — вопрос и эталонный ответ; из результата запуска — ранжированный список фрагментов, возвращённых поиском.

**Как считается.** Полезные фрагменты должны находиться как можно выше в ранжированном списке; нерелевантные результаты снижают значение метрики.

**RAGAS.** Context Precision.

## 4. Служебные показатели выполнения

Помимо качества оценщик сохраняет несколько показателей эффективности. Они нужны, чтобы отличать две версии с одинаковым качеством и выбирать ту, которая достигает результата с меньшим числом действий и меньшими затратами вычислений.

| **Показатель**                      | **Что означает**                                                           |
|-------------------------------------|----------------------------------------------------------------------------|
| Общее число вызовов инструментов    | Сколько раз агент обращался к инструментам при обработке запроса.          |
| Число успешных вызовов инструментов | Сколько вызовов завершилось успешно.                                       |
| Общее число токенов                 | Сколько токенов было использовано за всю обработку запроса.                |
| Время обработки запроса             | Сколько времени прошло от начала обработки до получения финального ответа. |

При сравнении версий приоритет остаётся за качеством ответа. Если качество сопоставимо, предпочтительнее версия, которая делает меньше вызовов инструментов, использует меньше токенов и быстрее отвечает.

На уровне всего эксперимента оболочка дополнительно сохраняет длительность одной итерации оптимизации и общее время оптимизации.

## 5. Обработка одного тестового запроса

Сначала проверяется, завершился ли запуск и есть ли данные, достаточные для базовой оценки. После этого каждая метрика рассчитывается отдельно.

Если агент не завершил обработку запроса или не вернул финальный ответ, такой запрос помечается как неуспешный и не входит в средние показатели качества.

Если запрос выполнен, но при расчёте одной из метрик произошла ошибка, значение этой метрики помечается как отсутствующее. Оно исключается только из среднего по этой метрике; остальные результаты запроса продолжают учитываться. Причина ошибки сохраняется во внутренних данных, чтобы было видно, почему число значений для разных метрик может отличаться.

## 6. Сводные показатели по тестовому набору

После обработки всего набора для каждой метрики считается обычное среднее по тестовым запросам. Каждый вопрос имеет одинаковый вес, независимо от того, сколько эталонных фактов размечено для него.

В среднее по конкретной метрике входят только те запросы, для которых её удалось рассчитать. Вместе со средним значением сохраняется число запросов, вошедших в расчёт. Благодаря этому всегда видно, насколько полно была посчитана каждая метрика.

| **Показатель**          | **Пример**          | **Как читать результат**                                            |
|-------------------------|---------------------|---------------------------------------------------------------------|
| Всего тестовых запросов | 100                 | Размер тестового набора.                                            |
| Успешно завершено       | 94                  | Для 94 запросов агент вернул результат, пригодный для оценки.       |
| Не завершено            | 6                   | Шесть запусков не дошли до результата, пригодного для оценки.       |
| Fact Recall             | 0,78 по 94 запросам | Среднее рассчитано по всем успешно завершённым запросам.            |
| Faithfulness            | 0,91 по 90 запросам | Для четырёх завершённых запросов значение этой метрики отсутствует. |
| Context Precision       | 0,84 по 88 запросам | Среднее построено по 88 корректно рассчитанным значениям.           |

Служебные показатели также усредняются по успешно завершённым запросам, для которых есть соответствующее значение.

## 7. Что сохраняется внутри системы и что видит пользователь

| **Уровень**               | **Что сохраняется**                                                                                                                      | **Кто использует**                                                       |
|---------------------------|------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------|
| Отдельный тестовый запрос | Значения метрик, служебные показатели, отсутствующие значения и причины ошибок расчёта.                                                  | Диагностика и модуль оптимизации.                                        |
| Версия агента             | Средние метрики, число запросов в расчёте каждой метрики, число завершённых и не завершённых запросов, средние показатели эффективности. | Правило принятия кандидата, модуль оптимизации и интерфейс пользователя. |

Пользователю показываются сводные показатели версии. Подробные результаты отдельных запросов остаются внутренними данными системы и используются при диагностике и оптимизации.

## 8. Итог оценки версии

После обработки тестового набора оценщик формирует сводный результат для версии агента. В нём собраны показатели, по которым эту версию можно сравнить с исходной версией и с другими кандидатами.

| **Группа**               | **Что входит в итог**                                                                                                                                         |
|--------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Качество ответа и поиска | Средние Fact Recall, Fact Precision, Retrieval Fact Recall, Faithfulness и Context Precision; рядом с каждой метрикой — число запросов, вошедших в её расчёт. |
| Эффективность            | Среднее число вызовов инструментов, среднее число успешных вызовов, среднее число токенов и среднее время обработки запроса.                                  |
| Полнота оценки           | Общее число тестовых запросов, число успешно завершённых и число не завершённых запросов.                                                                     |

Подробные значения по каждому запросу сохраняются во внутреннем хранилище и остаются доступными диагностике и оптимизатору.

## 9. Технологии

| **Часть**                     | **Рабочее решение**               | **Как используется**                                                                                                                                                                                      |
|-------------------------------|-----------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Метрики качества              | RAGAS                             | Fact Recall — Factual Correctness (recall); Fact Precision — Factual Correctness (precision); Retrieval Fact Recall — Context Recall; Faithfulness — Faithfulness; Context Precision — Context Precision. |
| Модель для смысловых проверок | Настройки RAGAS                   | Модель используется внутри тех метрик RAGAS, где требуется смысловое сравнение утверждений, ответа и контекста.                                                                                           |
| Хранение результатов          | Внутреннее хранилище эксперимента | Подробные результаты по запросам, сводные показатели версии и причины ошибок расчёта метрик.                                                                                                              |

## 10. Как проходит оценка одной версии

**1.** Оценщик получает тестовый набор и результаты запуска выбранной версии агента.

**2.** Для каждого тестового запроса проверяет наличие необходимых данных и рассчитывает доступные метрики.

**3.** Подробные результаты сохраняет во внутреннем хранилище.

**4.** После обработки всего набора рассчитывает средние значения только по корректно полученным результатам и сохраняет число запросов, вошедших в расчёт каждой метрики.

**5.** Сводные показатели передаются системе для сравнения версий и показываются пользователю в интерфейсе.
